# Changelog

## [Unreleased]

### Added
- Added `EfficientAdDetector`: EfficientAD (student-teacher + autoencoder) anomaly map
  `scores [B, H, W, 1]` and top-k `anomaly_score [B]` of an RGB frame, with anomalib 2.1.0's
  `EfficientAdModel` used unchanged. The frame is resized with the stock pre-processor's
  antialiased bilinear resize and the map is resized back bilinearly, so the node reproduces
  anomalib's inference path exactly. Weights are frozen and the model is pinned to eval mode
  (anomalib returns losses in train mode); every tensor, including the teacher mean / std and the
  map quantiles, lives in the pipeline `.pt`.
- Added `EfficientAdDetector.load_anomalib_checkpoint`: strict import of an anomalib `EfficientAd`
  Lightning checkpoint or a tensors-only `{"state_dict": ...}` file; rejects foreign checkpoints and
  unvalidated ones (all-zero quantiles), and names the missing class when the checkpoint pickles
  training code that is not importable. The file is unpickled: load only trusted checkpoints.
- Declared anomalib 2.1.0's undeclared runtime dependencies (`open-clip-torch` for the eager WinClip
  import, `requests` for the video chain) and torch / torchvision, which anomalib only offers as extras.
- Added the local-path plugin manifest (`plugins.yaml`, metadata generated by `emit_metadata`; the
  README also shows the git-tag form) and tests: anomalib inference-path parity, image score, quantile
  normalisation, port contract, frozen state and eval pinning, checkpoint import and rejection,
  hparam validation, manifest loading, a pipeline reload smoke, and a slow parity test of a
  trained checkpoint against anomalib's inference path (`EFFICIENTAD_CKPT`).
- Added CI (tests on Python 3.11 and 3.13 for every pull request, lint, type check, security scan,
  build, release on `v*` tags) and a dependency compatibility audit against cuvis-ai-core v0.17.4.
- Added the `cuda` dependency group for local GPU development: torch and torchvision come from the
  cu128 index (cu130 on aarch64 Linux / Jetson). The pins are scoped to the group, so an
  environment that installs the plugin as a path or git dependency inherits none; a guard test
  checks this and that the committed lock (the CI lock) resolves torch from PyPI.
- Targets cuvis-ai-core >= 0.17.4 and cuvis-ai-schemas >= 0.12.0 on Python 3.11 – 3.13.
